# Internal DS18B20 probe

The internal low-temperature probe uses GP26, external 3.3 V power, common
ground, and an external data pull-up to 3.3 V. It remains separate from the
DHT22 temperature/humidity and external MAX31865/PT100 channels.

The normal monitor requests 12-bit conversions asynchronously, waits 800 ms,
and targets one conversion per second. ROM/scratchpad CRC validation, range
checks and invalid-sample rejection remain enabled. A failed transaction still
causes a five-second rediscovery delay. USB `INTERNAL_TEMP` lines include
`sampled_ms`, the MCU timestamp of the published success or failure.

## RP2040 OneWire timing

The pinned OneWire 2.3.8 RP2040 fallback uses generic GPIO APIs in timing-critical
slots. On the connected installation, raw ROM reads were corrupted, predominantly
by expected zero bits being read as ones. Direct SIO GPIO transactions worked
substantially better with the same connected probe and full peripheral workload.

`tools/onewire-rp2040-read.py` generates a build-directory copy of OneWire.cpp
with direct RP2040 read slots. The `custom_onewire_direct_writes` option also
replaces write slots. It does not edit the dependency cache or vendor the entire
library. Discovery, reset/presence handling, conversion, CRC and application
recovery remain in the original code. Changes to the pinned library require
reviewing the build-time replacement.

Read slots drive low for 3 us, release the line, and wait another 10 us before
sampling, with interrupts disabled through the sample. Write-one slots drive
low for 6 us; write-zero slots for 65 us. Write slots retain upstream strong-high
behavior and the byte-write routine's subsequent release/power handling.
Previous interrupt state is restored after each critical section.

The datasheet requires read sampling within 15 us of the falling edge and
write-one release within 15 us. Generic API overhead consumes the small margin
left by nominal delays. Exact electrical timing has not been scope-measured;
the diagnosis is supported by controlled firmware comparisons.

Reference: [DS18B20 datasheet, read/write slots](https://www.analog.com/media/en/technical-documentation/data-sheets/ds18b20.pdf).

## Reproducing the comparison

- `split_host_ds18_diagnostic`: full balloon workload, original library timing,
  alternating 30-second library/direct-GPIO protocol windows.
- `split_host_ds18_read_test`: same comparison with only library read slots fixed.
- `split_host_ds18_timing_test`: normal acquisition with read/write slots fixed.

The raw diagnostic assumes one installed DS18B20 on GP26, reads its ROM and
scratchpad, and checks their CRCs. It does not save EEPROM or relax validation.
Raw diagnostic sampling cadence differs from normal acquisition; compare the
success fractions rather than treating packet/report counts as equal durations.
Do not leave the raw comparison build installed after testing.

The bench checks do not establish
cold-temperature accuracy, flight reliability, or a cure for the separate USB
failure. Retaining the probe requires representative cold and duration testing.
